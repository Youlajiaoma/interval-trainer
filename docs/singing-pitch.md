# 模唱音准判定

本模块分析单人、单音的持续哼唱，复用项目的钢琴采样和 Web Audio 播放。没有录音文件、服务器分析或模型训练；麦克风数据只在浏览器内存中处理，退出模块、切到后台或打开设置会关闭麦克风。

## 为什么不能要求频率固定

人声存在自然的细小波动和颤音。Titze 对颤音与音准的讨论指出，应考虑波动的中心；文中也明确表示，不能简单断言有颤音或无颤音一定更准。因此程序观察一段发声的整体表现，不用单个瞬时频率决定正误。

## 当前实现

- 使用 YIN 的差分与累积归一化思路估计基频，寻找周期性局部低点，并作抛物线插值。基频是决定音高的基本振动频率，不能直接选频谱中最大的泛音峰。较高采样率先分组平均降采样，复用分析数组，每秒分析约 20 次。
- 分析约 32～2200 Hz；去除直流偏移，低于均方根振幅 0.006 的声音不作为有效发声；周期可信度至少 0.85。安静或非周期噪声断开曲线，不把上次音高延长到静音中。
- 原先直接将每次检测结果连线，并立即据此调整纵轴，单帧较大的误估会显示成向下的深尖刺。现在首次音高及超过 3 个半音的突变需连续确认至少 3 帧、100 毫秒；超过 9 个半音的突变需持续至少 200 毫秒。未确认的数据不画点、不判题，形成短暂断线；确认后的大跳也不连接垂直线。这套跟踪不使用目标音修正结果，持续唱出的其他音和高低八度仍显示实际检测音高。
- 以 A4 = 440 Hz 的十二平均律为参考，将偏差换算成音分（一个半音是 100 音分）。偏差按 1200 音分循环，因此检测范围内的整八度差异都接受；图上仍显示实际检测到的八度。
- 观察最近 1.2 秒，至少积累完整 1.2 秒的检测过程才判定；有效发声占观察时间至少 80%，其中至少 80% 在目标的 ±50 音分内，按时间加权的偏差中位数在 ±35 音分内才通过。允许轻微抖动和少量漏检，持续偏高、偏低、滑过目标及长时间断续不通过。超过 150 毫秒没有新分析会重新累计，避免后台卡顿制造“持续唱准”。
- 点击播放时申请麦克风权限，为浏览器处理授权和音频启动保留用户手势；钢琴播放及结束后 450 毫秒不分析、绘制或判题。授权就绪且等待结束后，自动开始检测，绿色麦克风显示「可以模唱」。如果授权较晚，等待授权完成后才开始，等待期间不亮绿灯。成功后自动关闭麦克风、停止曲线更新，显示「正确」并保留已画曲线。
- 钢琴参考音恢复最初的 1.5 秒时长，保留原速、原音高。模唱过程中点击重播会立即停止旧麦克风；重新取得的音频轨道在等待期间关闭输入，播放结束后才启用，恢复模唱。
- 出题音域默认 C3～C5，可设置为 C2～C6 内任意上下限，包含半音和端点，可固定单音。下一题播放新音并开始新一轮检测；重播清空本次曲线、重新模唱当前题，已经完成的题目不会重复计数。寻找音高不逐帧计为答错，只有完成的模唱计入统计和每日任务。

上述门槛是首版练习的产品设定，并非论文给出的统一音准标准；需要结合真人、设备、房间和环境音继续调整。合成信号测试不能证明所有人声都能正确识别。单个麦克风也无法保证区分用户嗓音与外部乐器、他人声音，建议在较安静的环境试用；必要时戴耳机减少串音。

## 验证与限制

`tests/test_pitch.cjs` 检查多种采样率、低中高音、强泛音、噪声，以及时间窗口、自然抖动、短暂经过、八度和相邻半音；还检查短暂的向下误估被过滤、真实持续变化仍能显示。`tests/test_singing.cjs` 检查入口、音域、重播、原记录保护、统计和备份兼容。`tests/test_singing_browser.cjs` 用浏览器真实 Web Audio 生成的信号作为模拟麦克风，检查完整检测链、自动开始/停止、提示颜色、短暂跳变断线、授权异常和麦克风释放，数据与日常浏览器隔离。它不等于真人或实体麦克风验收；短暂误估回归检查也不代表已经确认用户截图中每次尖刺的声学原因。

麦克风必须由用户点击后授权；浏览器要求 HTTPS 或可信的本机地址。电脑可用 `http://localhost:8000/`。手机直接访问电脑的普通 HTTP 局域网地址通常无法授权，需要 HTTPS；拒绝授权、设备不存在和设备断开会显示对应说明。
