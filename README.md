# Tonaloom

Tonaloom 是一个面向日常练耳与基础识谱的网页练习工具，包含四个练习模块、学习统计和间隔复习。无需注册账号，练习记录保存在本机；支持手机、电脑和离线使用。

**[打开 Tonaloom，开始练习](https://youlajiaoma.github.io/interval-trainer/)**

## 四个练习模块

| 模块 | 练习方式 | 主要特点 |
| --- | --- | --- |
| 和声音程 | 同时听两个钢琴音，选择音程 | 纯一度至纯八度，共 13 种答案；可调整音程范围、音区和播放时长，答题后可「分开听」 |
| 旋律音程 | 先后听两个音，选择音程 | 小二度至纯八度，共 12 种答案；使用钢琴、古典吉他、中音萨克斯和长笛的预录音频，分别记录上行、下行的掌握情况 |
| 音符辨认 | 看五线谱，通过钢琴键盘选择音符 | 每组 20 个音符，分三行展示，包含不同节奏；可选高音谱号、低音谱号或混合出题，可设置是否包含升降号 |
| 音程辨认 | 看五线谱上的两个叠置音符，选择和声音程 | 每组 10 题，高音、低音谱号各 5 题；使用与和声音程相同的 13 种答案选项 |

音符辨认使用带黑键的键盘作答，**不要求判断八度**。答错后可留在原题重答；答对后播放谱面对应音高的钢琴声，再进入下一题。音程辨认答对后同时播放两个音，并自动进入下一题。这两个识谱模块都支持显示答案、开始下一组，以及返回后继续未完成的练习。

## 统计与复习

- 四个模块分别保存学习情况，共用一致的统计页面；音符辨认还区分谱号和音符位置。
- 可按近 7 天、近 30 天、近 90 天或全部时间查看答题总数、正确率、练习天数和连续练习天数。
- 提供正确率与练习量趋势、练习日历、分类表现、易混淆内容、复习安排和答题记录。
- 根据错题和到期的复习安排，自动增加相应内容的练习机会。

## 使用与离线访问

打开[正式网站](https://youlajiaoma.github.io/interval-trainer/)，在首页选择模块开始练习。练习界面右上角的齿轮用于调整设置，首页的「查看统计」用于查看各模块的学习情况。

支持的浏览器可以通过「添加到主屏幕」或「安装应用」将 Tonaloom 作为 PWA 使用，即从桌面独立启动的网页应用。

首次访问需要联网，等待网页、谱面绘制和音频资源完成缓存。之后可离线使用已缓存的内容；未缓存的旋律录音仍需要联网加载。出现「发现新版本」时，可在应用内更新。

## 数据保存与备份

练习记录、复习进度和设置保存在**当前设备、当前浏览器的 IndexedDB 本地数据库**中，不会自动同步到其他设备。

进入「练习统计 → 数据备份与管理」，可以导出 JSON 备份，或从备份恢复学习记录和设置。**导入会覆盖备份中包含的对应记录与设置，建议先导出当前数据。** 未完成题组的页面进度不等同于学习记录备份，不保证全部恢复。

清除网站数据、更换设备或卸载应用前，请先导出备份。不同浏览器、网站域名或本地端口的数据彼此独立，不会自动迁移；例如正式网站与本地预览不共用记录。

## 本地运行

项目是静态网页，无需构建或安装 npm 依赖。安装 Python 3 后，在项目根目录运行：

```powershell
python -m http.server 8000 --directory site
```

在浏览器中打开 <http://localhost:8000/>。使用期间保持终端运行；按 `Ctrl+C` 停止服务。请通过本地服务访问，不要直接双击打开 HTML 文件。

五线谱使用固定版本 VexFlow 5.0.0。当前仓库不附带 `site/vendor/vexflow.js`，本地首次预览会联网从 CDN 加载；GitHub 自动检查和正式部署会补齐该文件。若要在本地验证完整离线使用，需要先在该路径放入同版本的[上游发布文件](https://cdn.jsdelivr.net/npm/vexflow@5.0.0/build/cjs/vexflow.js)，并保留相应许可证。

## 开发与测试

主要技术是原生 HTML、CSS 和 JavaScript，使用 Web Audio API 播放声音、[VexFlow](https://github.com/vexflow/vexflow) 绘制五线谱、IndexedDB 保存数据，以及 Service Worker 和 Web App Manifest 实现离线缓存与应用安装。无需后端服务。

| 路径 | 内容 |
| --- | --- |
| `site/index.html`、`site/styles.css`、`site/sight.css` | 网页入口和样式 |
| `site/app.js`、`site/logic.js`、`site/modules.js` | 练习流程、音程逻辑和模块管理 |
| `site/sight.js`、`site/staff-interval.js` | 音符辨认和音程辨认 |
| `site/audio.js`、`site/assets/` | 声音播放、采样和旋律录音 |
| `site/review.js`、`site/statistics.js`、`site/storage.js` | 复习安排、统计和本地存储 |
| `site/sw.js`、`site/pwa-register.js`、`site/manifest.webmanifest` | 离线缓存、版本更新和应用安装 |
| `tests/` | 自动测试及测试说明 |
| `.github/workflows/` | GitHub 自动检查和 Pages 部署配置 |

基础检查使用 Node.js 自带工具。GitHub 自动检查使用 Node.js 24，建议本地采用相同版本。在项目根目录运行：

```powershell
node tests/run.cjs
```

基础命令会区分通过、失败和跳过。完整检查使用 `node tests/run.cjs --full`，还需要 Playwright、Chromium、本地 VexFlow 文件及本地网页服务；缺少条件而跳过也会使完整检查失败。环境准备、覆盖范围和具体用法见[测试说明](tests/README.md)。

日常开发使用 `dev` 分支，正式版本使用 `main`；修改前请阅读 [AGENTS.md](AGENTS.md)。推送 `dev` 会触发自动检查；`main` 的 Pages 部署在完整检查通过后进行。自动测试通过后，仍需检查实际页面、手机布局和声音效果。

版本变化见 [CHANGELOG.md](CHANGELOG.md)。
